# 质检表：判断标准与收尾检查

提示词工厂的收尾关卡。**P 层标准为主，C/R 是补充检查**——本厂主攻提示词本身，供料与权限只在提示词涉及「它要读什么、它能动什么」时补查。

## P 层五条判断标准（主检）

| 招 | 初阶 | 高阶 | 判断标准 |
|---|---|---|---|
| 正 | 五要素：背景/角色/任务/格式/限制 | 行业大脑六招 | 产出像不像「我们公司出品」 |
| 反 | 我是傻子＋要最佳实践；成品反推 | 盲区扫描、专家会诊、倒推字段、费曼拷问、拆成品六问、双层解释、Grill me、苏格拉底 6 问 | 能不能替我找出看不见的坑 |
| 合 | 结构先定好，再让它按结构填内容（结构归你，内容归它） | — | 结果稳不稳定、能不能批量 |

加两道通用保险（任何模式收尾都过）：

- **收口两句**：产出不满意先加「请一步步思考」「很好，请继续」，再谈重写
- **溯源反问**：涉及数字和事实的产出，问一句「依据是哪些数据」，追溯不到就打回

## C/R 补充检查（提示词涉及资料与动手时才查）

| 补充项 | 检查问题 | 参考 |
|---|---|---|
| C 供料 | 这条提示词要的资料，这次贴进去（附件）够不够？天天贴同一份 → 该挂上去（知识库）；数据一直在变 → 得连过去（连接器/MCP） | context-rights.md |
| C 口径 | 它答得出「我们去年怎么做的」吗——缺历史口径就在提示词里补样例或指路 | context-rights.md「文件夹即大脑」 |
| R 边界 | 动作限制写了吗（不改原始文件/不对外发送/不做账号操作）？安全边界交代了吗？ | context-rights.md |
| R 自主 | 要不要留自主空间（「发现更好做法请主动告诉我，并解释怎么实现」）？ | context-rights.md 决策权限 |
| R 执行 | 低风险重复任务，建议定时跑——先半自动两周再全自动 | context-rights.md 执行权限 |

## 自查顺序

先问 P 够不够（说不说得清）→ 再问 C 够不够（有没有资料）→ 最后问 R 够不够（让不让动手）。

**顺序别倒**——很多人一上来就买工具、接连接器，结果 P 和 C 都是空的。

## 三层是乘法，不是加法（为什么 C/R 不能完全省）

| 只强在一层 | 表现 | 缺的 |
|---|---|---|
| 只有 P | 提示词写得漂亮，产出永远像「网上抄的」，写得再好也不知道你公司的口径 | C |
| 只有 C | 资料喂了一堆，产出照样发散、抓不住重点、格式不对 | P |
| 只有 R | 自动化跑得挺欢，跑出来的东西没人敢用 | P＋C |
| P＋C | 产出质量够了，但每一步都要手动点，你还是那个搬运工 | R |

三层递进，对应省下的三种时间：P 省打字时间，C 省解释时间，R 省整个流程的时间。真正拉开差距的是第三层——你不在工位的那八小时，AI 还在不在干活。
