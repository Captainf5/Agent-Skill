# 场景挖掘（bobo-mining / AI Scout）

回答两个问题：① 我的工作里哪些最适合 AI 化？② 最佳场景怎么变成一份能交出去的轻量级 PRD？

## 五道筛子（AI 适配度评估标准）

每项工作任务逐项过筛，全过 = 高适配场景：

| # | 筛子 | 判断口径 |
|---|---|---|
| 1 | 高频 | 天天/每周做，不是一年一次 |
| 2 | 重复 | 步骤稳定可复制，不靠临场发挥 |
| 3 | 规则明确 | 判断标准说得出口、写得出 |
| 4 | 结构化 | 输入输出有固定格式（表格/模板/固定话术） |
| 5 | 容错 | 出错有人工复核兜底，不致命 |

隐性前提：**素材在公司内拿得到**。涉密/跨系统拿不到的场景，单独标注「需信创/本地化方案」。

## 两段式工作流

```
勘探 interview → 锁定 TOP1 场景 → 开采 prd → 入场景库 archive
```

**勘探阶段不许写 PRD。** 场景没盘清就写需求，是甲方 AI 项目失败的第一大原因。

## 路由

- 盘点工作任务、筛场景、排适配度 → 读 `references/bobo-mining-interview.md`
- 场景已锁定，要写需求文档 → 读 `references/bobo-mining-prd.md`
- 定稿要入库 / 下次盘点前先读库 → 读 `references/bobo-mining-archive.md`
- 要去别的 AI 工具里用（无 Skill 环境）→ 复制 `references/bobo-mining-一键版.md` 整段粘贴

## 开场

一次一问，附推荐答案，文档里已有的信息不要问：
1. 岗位和日常工作内容是什么？（可粘贴岗位说明 / 周报 / 流程文档）
2. 盘点范围：只看个人，还是团队/部门？

## 场景库位置

优先使用当前项目已有场景库；尚未配置时在用户确认的工作区保存 `bobo-mining-library.md`。WorkBuddy已有 `.workbuddy/bobo-mining/` 或 `~/.workbuddy/bobo-mining-library.md` 时沿用原库，不为安装创建第二份。

## 授课/工作坊用法

20 人现场盘点 → 部门级场景地图；五道筛子打分环节天然形成小组讨论。
