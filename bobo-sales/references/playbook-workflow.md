# 作战包生成流程

拿到一个政企/ToB 商机后，按 0–6 段顺序产出。每段都有**判据**，达不到判据就写"待补"，不许编。

---

## 0. 商机速览（先对齐事实）

列出：客户单位 / 行业 / 我方要卖的东西 / 项目阶段 / 我方已做动作 / 已知时间节点 / 金额量级（如未知写"未掌握"）。
**凡未掌握的信息一律标「待补」，不得用假设填充后当作事实输出。**

---

## 1. 决策链地图 — Miller Heiman

按 Economic / Technical / User / Coach 四类填表：

| 角色 | 姓名或岗位 | 关注点 | 对我方态度（支持/中立/反对/未知） | 接触状态 | 下一步 |
|---|---|---|---|---|---|

**判据**
- 四类至少确认三类；Coach 未确认时必须显式写出「**本单目前无教练**」。
- Coach 必须通过三条件检验（你信他 / 他信你 / 他希望你赢）。只满足前两条的不算教练，标为「线人」。
- 一人身兼多角色的，在同一行注明，不要拆成两个人。
- 未接触到的角色标「未接触」，不要推测其立场。

---

## 2. 资格判定 — MEDDIC

六要素逐项判定：`已确认 / 部分确认 / 未确认`，每项必须跟一句**依据**（谁说的、哪里看到的）。

**判据**：任何一项为「未确认」，该单即为**资格不足**，必须在结论里点名。
缺 **E**（经济买家）或 **C**（冠军）时，直接给出「暂不建议继续投入资源」的判断，并说明补哪个缺口、怎么补。

打分调用：
```bash
python scripts/qualify_opportunity.py brief.json
```

---

## 3. 商业洞察 — Challenger

产出**一个**洞察，按三段式写：
1. **客户不知道的事实**：一条与客户业务相关的行业/经营事实（必须可核查，不确定的标"待核实"）
2. **代价量化**：这条事实每年/每月给客户造成的成本、风险或错失的收益
3. **Lead to**：这条事实**自然引向**我方哪一样**独有**能力

**判据**
- 洞察之后接的必须是**我方独有**的能力。如果接的是"人人都能做"，这段洞察作废，重做。
- Tailor：同一洞察必须给出**两个版本**——讲给经济买家（钱/风险口径）和讲给用户买家（工作量/流程口径）。
- 拿不出真洞察时，如实写「本单暂无可支撑的挑战者洞察」，改用 SPIN 的 I 类提问去现场挖，**不要硬编**。

---

## 4. 提问清单 — SPIN

按拜访实际顺序排列，**S 类不超过 2 条**，I 类和 N 类是主力。

| 顺序 | 类型 | 提问原话（口语，可照念） | 想听到什么 | 听到后接什么 |
|---|---|---|---|---|

**判据**
- 每条必须是**销售能当场说出口**的大白话，不许书面语翻译腔。
- I 类要让客户自己推导出代价，不许写成"不解决会不会很惨？"这类威胁句。
- N 类必须让客户自己说出价值，不许由销售替客户总结。
- 每个关键提问后写「听到 X 就往 A 走，听到 Y 就往 B 走」，否则清单没有执行价值。

---

## 5. 异议与谈判预案 — Voss + Cialdini

挑出本单**最可能出现的 2–3 个异议**（常见：预算没批 / 已有供应商 / 先做个试点 / 价格太高 / 领导不点头）。
每个异议按三步写：
1. **标注**（说出对方处境）
2. **校准式提问**（What/How 开头，不用 Why）
3. **回应**（我方事实 + 社会认同或权威佐证）

**判据**
- 校准式提问必须是 What/How 开头，出现 Why 开头的判定不合格。
- 佐证必须是**真实存在**的案例/报告/资质；没有就写「暂无佐证，需准备」，不得虚构案例或数据。
- 谈判工具不得用在开场——客户尚未承认痛点时先标注，会显得油滑。

---

## 6. 下一步动作 — SSO + 承诺目标

**单一销售目标 SSO**：只写一个，必须**具体、可验证、客户愿意给**。
反例（不合格）："加深客户关系""保持沟通""推进项目"。

**承诺目标三级**
- **Best**：最想要的结果
- **Expected**：预期能拿到的结果
- **Minimum**：低于这个，就该复盘是否继续投入

**判据**：三级必须都能被第三方观察到是否达成。写不出可验证的 Minimum，说明这次拜访目标不清晰，打回第 0 段重来。

---

## 收尾（必写）

1. **资格总分**（来自 scripts 或 rubric）
2. **三个最大缺口**（按对成交的影响排序）
3. **SSO 与 Minimum**
4. **本单的合规提醒**（至少一条，从 frameworks.md 第 9 节红线里取）
5. **本单的本土提醒**（过一遍 `china-context.md` 的七条偏差，命中的写成具体动作：谁、什么场合、怎么开口）
