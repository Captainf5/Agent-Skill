## 1. SPIN Selling — 提问结构

**出处**：Neil Rackham, *SPIN Selling*, McGraw-Hill, 1988。基于 Huthwaite 对大型销售拜访的实证研究。

**四类提问**（置信：高）

| 类型 | 作用 | 大单中的使用原则 |
|---|---|---|
| **S** 背景问题 Situation | 摸清现状 | **越少越好**。问多了客户烦，且拉低成交相关性 |
| **P** 难点问题 Problem | 找痛点/困难/不满 | 中等量，用来定位真实缺口 |
| **I** 暗示问题 Implication | 放大痛点的连锁后果与代价 | **大单的核心**。把"有点麻烦"放大成"必须解决" |
| **N** 需求-效益问题 Need-Payoff | 让客户自己说出解决后的价值 | **收口用**。让客户自己论证，比销售自夸有力得多 |

**核心结论**（置信：中）：在大额销售中，成交与 **N 类提问**强正相关，与 **S 类提问**负相关。
**出处与置信**：该结论为 SPIN 的标志性发现，行业引用极广；"35,000 次销售拜访"这一样本数在不同版本与二手转述中口径不一（另有 12,000 / 上万次的说法），**引用时写"对数万次销售拜访的实证研究"，不要写死具体数字**（置信：中，约 70%）。

**边界**：SPIN 面向**大额、长周期、多决策人**的销售。小单、快消、纯电销场景收益有限，不要用。
**典型误区**：把 I 类问题问成威胁（"不解决会不会很惨？"）——那叫吓唬，不叫暗示。I 类要让客户自己推导出代价。

## 2. The Challenger Sale — 价值主张与角色定位

**出处**：Matthew Dixon & Brent Adamson (CEB), *The Challenger Sale*, Portfolio/Penguin, 2011。基于 CEB 对全球销售队伍的调研。
**样本**（置信：中，约 70–75%）：常见引用为覆盖 90 余家公司、6,000 名以上销售代表。引用时写"对数千名销售代表的调研"。

**五型销售画像**（置信：高）
1. **Challenger 挑战者** — 教客户新东西，主导对话（大单环境胜出率最高）
2. **Lone Wolf 独狼** — 自信、按自己方式打
3. **Hard Worker 勤奋型** — 不计较付出
4. **Reactive Problem Solver 问题解决型** — 响应快、可靠
5. **Relationship Builder 关系型** — 人缘好、易相处

**Challenger 三要素 Teach–Tailor–Take Control**（置信：高）
- **Teach 教**：给客户一个他不知道、且与自身业务相关的商业洞察
- **Tailor 定制**：同一洞察，讲给财务负责人和讲给技术负责人，说法必须不同
- **Take Control 控场**：敢于在价格、节奏上主导，不无底线迁就客户

**商业洞察的收口原则**（置信：中高）：洞察不能直接落到"所以我们产品好"，必须 **Lead to** —— 先指向一个客户未曾意识到的成本/风险/机会，再自然引向我方**独有**的解决能力。若洞察之后接的是人人都能做的事，就白讲了。

**边界**：挑战者打法的前提是你能说出**真的有信息量**的东西。没有洞察硬装挑战者，会变成说教，比关系型更糟。

## 3. The New Strategic Selling — 决策链地图

**出处**：Robert B. Miller & Stephen E. Heiman, *The New Strategic Selling*, Warner Books, 1989（初版 *Strategic Selling* 1985）。

**四类决策角色**（置信：高）
| 角色 | 关注什么 | 判定标准 |
|---|---|---|
| **Economic Buyer 经济买家** | 钱花得值不值、ROI、组织目标 | 能批钱、能说不、能改变资金用途 |
| **Technical Buyer 技术买家** | 合规、标准、技术可行性 | 能一票否决，负责筛选与把关 |
| **User Buyer 用户买家** | 好不好用、会不会增加我工作量 | 真正要使用/管理者 |
| **Coach 教练** | 帮你赢的人 | 三个条件：你信他、他信你、他希望你赢 |

**Coach 判定三条件**（置信：高）：① 你信任他；② 他信任你；③ 他有动机希望你赢。
三者缺一都不算教练——信息灵通但不想你赢的人，只是线人。

**单一销售目标 SSO**（置信：中高）：每次拜访/每个阶段只设一个**具体、可验证、客户愿意给**的承诺目标，而不是"推进关系""加深印象"这类无法验证的东西。

**承诺目标分级**（置信：中，要素可靠，分级命名在不同教材里叫法不一）：
**Best**（最想要）/ **Expected**（预期能拿到）/ **Minimum**（低于这个就该复盘是否继续投入）。

**Win-Win 矩阵**（置信：中）：同时看「我方得到什么」与「客户得到什么」，只有一侧赢的单子走不远。

**边界**：一人可身兼多角色；角色会随项目阶段变化。画完地图要标"未接触/身份待确认"，不能默认。

## 4. MEDDIC — 商机资格判定

**六要素**（置信：高）
| 要素 | 问什么 |
|---|---|
| **M** Metrics | 客户认可的可量化收益是什么？谁认这个数？ |
| **E** Economic Buyer | 找到了经济买家并接触上了吗？ |
| **D** Decision Criteria | 客户的决策标准是什么？我们能影响其形成吗？ |
| **D** Decision Process | 完整采购流程是什么？卡点与时间表？ |
| **I** Identify Pain | 客户承认的痛点是什么？不解决的代价他认可吗？ |
| **C** Champion | 有内部冠军吗？他在替我们说话吗？ |

**起源说明**（置信：中，约 65%，存在争议）：MEDDIC 通常归于 1990 年代 PTC 公司的销售方法论实践（常见说法关联 Jack Napoli），但流传版本较多、起源叙述不统一。**不要对外断言单一发明人**。
**系统阐述复杂销售的参考著作**：Jeff Thull, *Mastering the Complex Sale*, 2005（置信：中高）。

**用法**：六要素**缺一即视为资格不足**。缺 C（Champion）和缺 E（Economic Buyer）是最致命的两个缺口——大量"看起来在推进"的单子，最后都死在这两项上。

## 5. The Trusted Advisor — 信任建设

**出处**：David H. Maister, Charles H. Green, Robert M. Galford, *The Trusted Advisor*, Free Press, 2000。

**信任公式**（置信：中高）
**Trust =（Credibility 可信度 + Reliability 可靠度 + Intimacy 亲近感）÷ Self-orientation 自我导向**
- 分子是加法形式（另有乘法变体流传，属不同教学版本，本 Skill 采用通行加法形式）
- 分母是**除数**：自我导向越高，信任被稀释得越狠。销售一开口就推产品，等于把分母拉大

**边界**：信任公式用于**长期关系与顾问型销售**。一次性的低价竞标场景，信任权重低于价格权重，别硬套。

## 6. Never Split the Difference — 谈判与异议

**出处**：Chris Voss with Tahl Raz, *Never Split the Difference*, HarperBusiness, 2016。作者为前 FBI 国际绑架谈判代表。

**可用技法**（置信：高）
- **战术同理心 Tactical Empathy**：先说出对方的处境与感受，让对方感到被理解，再谈条件
- **标注 Labeling**："看起来您这边最卡的是预算审批的时间点，是吗？"——把情绪/顾虑命名出来
- **校准式提问 Calibrated Questions**：用 **What / How** 开头（不用 Why、不用 Yes/No），把压力还给对方
  - "您需要我们怎么调整，这件事才推得动？"
  - "如果按这个节奏，您这边哪一步会先卡住？"
- **镜像 Mirroring**：重复对方最后几个字，逼对方继续说
- **接受"No"**：让对方能说 No，对方才会真的考虑。一路逼 Yes 得到的承诺是假的

**边界**：这是**谈判与异议**工具，不是开场工具。客户还没承认痛点就用标注，会显得油滑。

## 7. Influence — 说服力底层

**出处**：Robert Cialdini, *Influence: The Psychology of Persuasion*, 1984（后有增补版）。

**六原则**（置信：高）：互惠 Reciprocity / 承诺与一致 Commitment & Consistency / 社会认同 Social Proof / 喜好 Liking / 权威 Authority / 稀缺 Scarcity。
**第七原则**（置信：中）：较新版本加入 Unity 共同体，存在版本差异，引用时说明"部分版本"。

**政企场景最有效的两条**（本 Skill 判断，非原著排序）：
- **社会认同**：同行业、同体量、同主管部门的**可比标杆案例**，比任何功能描述都管用
- **权威**：第三方检测报告、标准化组织背书、专家评审意见，在政企里权重高于销售口述

**边界**：原则用于**呈现既有事实**，不用于制造虚假稀缺（如假称"只剩最后一个名额"）。

## 8. SNAP / 切入大客户

**出处**：Jill Konrath, *Selling to Big Companies*, 2005；*SNAP Selling*, Portfolio, 2010/2011（出版年在不同资料中有 2010 与 2011 两种说法，置信：中）。

**SNAP**（置信：中高）：**S**imple 简单 / **iN**valuable 极高价值 / **A**ligned 对齐客户优先事项 / **P**riority 挤进优先级。
**核心洞察**（置信：中）：大客户不缺供应商，缺的是**能减少他决策负担**的人。切入点是帮客户把问题定义清楚，而不是推销方案。

## 9. 政企/ToB 场景落地映射层（⚠️ 本 Skill 补充，非原著内容）

以下不属于任何一本书，是本 Skill 为政企场景补的**映射规则**，使用时不要冠以原著名义。

> **人情社会下的框架偏差，另见 `china-context.md`（L6 本土校准层，七条偏差）。**
> 本节只讲角色与流程的对应关系与合规底线；"框架在中国哪里会失灵、怎么修"在那一份里。

**角色映射**
| 框架角色 | 政企常见对应 | 备注 |
|---|---|---|
| Economic Buyer | 分管副职 / 一把手 / 董事会层面 | 金额越大越往上；小型项目可能落到部门正职 |
| Technical Buyer | 信息化/技术部门、采购中心、外部评标专家 | 常握有实质否决权，是最容易被忽略的杀手 |
| User Buyer | 业务处室、一线使用部门 | 他们的抵触是上线后失败的主因 |
| Coach | 项目经办人、对口处室联系人 | 必须验证"他希望你赢"这一条 |

**典型流程节点**：需求提出 → 立项 → 预算落实 → 方案/可研 → 招标文件与参数 → 评标 → 公示 → 合同 → 实施 → 验收 → 回款。
**最有价值的介入点**：**需求与参数形成之前**。等到招标文件挂网，胜负基本已定。

**合规红线**（不可协商）
- 禁止任何形式的利益输送、回扣、围标串标、陪标、探听或泄露标底、承诺中标。
- 合规打法只有：需求引导、技术参数前置沟通、评分办法研究、资质业绩准备、方案差异化。
- 涉及政府采购与国企采购的，以客户方公开发布的采购制度与《招标投标法》等现行法规为准；本 Skill 不提供法律意见，需要时建议客户方法务确认。
